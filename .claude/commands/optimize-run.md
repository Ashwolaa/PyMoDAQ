---
description: Executive: carry out approved tasks of the plan on agent branches within the budget
argument-hint: "[scope | task-id] [--explain]"
---

You are the coordinator of the executive. Arguments: `$ARGUMENTS`. Scope = package or `package/slice`, a task id (`T-...`), or empty to take the next scope with approved tasks in dependency order.

0. Note the start time first: `date -u +%FT%TZ` (START). The ledger measures this run's tokens from it.
1. Read `.agents/core/layers.md`, `.agents/core/rules.md`, `.agents/profile.toml`. Run `python3 .agents/scripts/budget.py check` and `budget.py disable-check`; stop on STOP/DISABLE after writing the handoff.
2. If `.agents/budget.toml` `[pilot] mode = "explain"` or `--explain` is given: list what you would do, write `.agents/reports/<scope>/<date>-run.md`, change nothing else.
3. Make sure you are on `dev_agent` (see `scripts/sync_branches.sh`); never touch `dev`.
4. Adopt the cocoordinator role (`.claude/agents/cocoordinator.md`) for the scope. Per task, from `dev_agent`: `git switch -c agent/<scope>/<specialty>/<date> dev_agent` (if that name exists, append `-<short-topic>`). The run id is `<date>-run-<task-id>` (formats.md).
4b. **Rework** (a task whose plan status is `blocked — review: ...`): reuse its registered branch instead of creating one: `git switch <branch>`, `git rebase dev_agent` (a conflict: `git rebase --abort`, plan `blocked — conflicts with dev_agent, rerun the task`, stop that task). The review reports are `.agents/reports/<scope>/*-pr-review-<task-id>*.md`; if two or more already say `verdict: changes`, do not rework: plan `blocked — review: still failing after 2 rounds, for the human`. Otherwise launch the task's specialist with the task block **and the latest review report**, told to fix exactly the findings listed there and nothing else. Same commit trailer, then steps 6-8; push with `--force-with-lease` if the rebase changed the head. In step 9 do not `registry.py add` (the row exists); the plan status becomes `done — branch <b>, CI <result>, reworked after review r<N>, awaiting review`.
5. Launch the specialist for each approved task with a folder-level scope. For tests launch one `test-agent` instance per test folder. Check `budget.py check` between tasks.
6. Before any push run `[checks]` for the touched scope and the layering test. Run the scope's tests once per `[checks].qt_backends` entry with `PYTEST_QT_API=<backend> QT_API=<backend>` and report both results. If a check fails, fix or stop; never skip or weaken a test. A failure that also happens on `dev_agent` is reported as pre-existing, with the command that showed it.
7. On the task branch commit **product files only, never anything under `.agents/`**, with the trailer `Agent-Run: <run-id>`. Push that branch. **Open no PR**: a PR is opened by `/optimize-merge` once `pr-reviewer` has validated the branch. Never open a PR upstream.
8. Run CI on the branch: `python3 .agents/scripts/ci.py run --branch <branch>` (dispatches the workflows that apply to the changed paths and waits; a push alone triggers nothing). Mypy only runs on PRs, so also run `mypy` on the touched files locally if the scope's package config has it. Green: go on. It reruns failed jobs once, reports jobs that pass on rerun as flaky, and compares what still fails with upstream/dev. Exit 0 = green. Exit 4 = green except failures upstream/dev has too: go on as green, run each printed `record:` line on `dev_agent` (it files the failure in `findings.jsonl` for the next `/optimize-plan`) and name the known failures in the plan status and PR body. Exit 1 = red: a failure upstream/dev does not have. Red: read the `gh run view <id> --log-failed` it prints, state whether the code or the infrastructure caused it, fix code failures on the branch, push and run again. Timeout (exit 2): record `CI pending`.
9. `git switch dev_agent`. State is written and committed **only here**: `registry.py add ... --status pushed` (no `--pr`); `plan.py set-status <plan> <task-id> "done — branch <branch>, CI <green|red|pending>, awaiting review"` (or `blocked — <reason>`); launch the `auditor`; overwrite `.agents/handoff/<scope>.md` (<= 40 lines, template in `handoff/_template.md`); `ledger.py add --run-id <run-id> ... --session current --since <START>`. Then `git add .agents && git commit -m "Log /optimize-run <task-id> (branch pushed, CI <result>)"` and `git push origin dev_agent`. `ledger.py`, `registry.py` and `plan.py` refuse to run on any other branch.
10. Report in <= 20 lines, ending with the branch, the CI result (with run URLs) and the paths of the files written. Next step for the human: `/optimize-merge <task-id>`.

Handle a rate-limit error by writing the handoff, logging `--outcome limit --session current --since <START>` and stopping.
